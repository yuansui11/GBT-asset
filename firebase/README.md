# 登录与数据安全：上线步骤

系统改用 Firebase Authentication 登录，密码不再写在代码和数据库里。按下面的顺序操作。

## 1. 开启登录方式（上线新版本之前）

Firebase 控制台 → 项目 `gambol-asset` → **Authentication** → **Sign-in method** → 开启 **电子邮件/密码（Email/Password）**。

不开启的话，新版本登录时会提示“登录服务未开启”。

## 2. 上线新版本，完成账号迁移

1. 合并代码，等 GitHub Pages 更新。
2. **超级管理员先用旧密码登录一次**，按提示设置新密码。设置完后，系统会自动把其他子管理员也迁移过去，并删除数据库里所有明文密码。
3. 子管理员下次用旧密码登录时，同样要先设置新密码。

迁移完成后，打开“权限管理”，确认所有账号旁边都没有“未迁移”标记。

## 3. 收紧数据库规则（迁移完成之后）

> 一定要在第 2 步完成后再做。规则收紧后，还没迁移的账号就无法再用旧密码登录了（超级管理员可以在“权限管理”里给它重新设密码）。

- Firebase 控制台 → **Firestore Database** → **规则（Rules）**：把 `firestore.rules` 的内容整个粘贴进去，点 **发布**。
- Firebase 控制台 → **Storage** → **规则（Rules）**：把 `storage.rules` 的内容粘贴进去，点 **发布**。控制台如果询问是否允许 Storage 读取 Firestore，选允许。

## 日常管理

- **新增账号**：权限管理 → “+ 子管理员”，填账号和初始密码。对方首次登录时要自己改密码。
- **忘记密码**：超级管理员在权限管理里给该账号填“重置密码”并保存。
- **停用账号**：在权限管理里删除该账号，对方立即无法访问数据。
- **修改自己的密码**：侧栏（手机上是“账号”菜单）→ 修改密码。

## 说明

- 账号在 Firebase 里对应 `账号名@asset.gambol.local` 这样的内部邮箱，不会真的发邮件，在 Authentication 的用户列表里能看到。
- 重置密码或删除账号后，Authentication 里可能留下旧的内部用户。它们已不在访问名单上，看不到任何数据，可以放着不管，也可以在控制台里删掉。
- 旧版本的密码曾经写在公开的代码里，所以迁移时会要求每个人都换新密码。
